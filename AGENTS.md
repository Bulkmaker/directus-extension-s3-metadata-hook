# AGENTS.md

Directus hook extension that sets the `Content-Disposition` header on S3 uploads, so files opened through an S3 or CDN URL download under their original filename instead of the stored UUID name.

## Commands

```bash
npm install
npm run build
```

`deploy.sh` (tracked) builds locally and restarts Directus through docker compose. No tests, no lint config.

## How it works

1. Listens to the `files.upload` event (after Directus has stored the file in S3).
2. Takes the original name from `payload.filename_download`.
3. Runs S3 `CopyObjectCommand` of the object onto itself with `MetadataDirective: REPLACE` (S3 cannot update metadata in place).
4. Sets `Content-Disposition: inline; filename="photo.jpg"; filename*=UTF-8''<percent-encoded>` (RFC 5987, so Cyrillic names work; `filename` is the ASCII fallback).

Environment variables read by the hook (names only): `STORAGE_S3_DRIVER` (must be `s3`, otherwise the hook stays inactive), `STORAGE_S3_REGION`, `STORAGE_S3_ENDPOINT`, `STORAGE_S3_KEY`, `STORAGE_S3_SECRET`, `STORAGE_S3_BUCKET`, `STORAGE_S3_ROOT` (optional prefix).

## Limitations

- Adds about 50-100 ms to each upload (extra CopyObject call).
- Credentials need `s3:GetObject` and `s3:PutObject`.
- Works only for new uploads; existing files are not changed.

## Build and release

- `dist/` is generated by GitHub Actions on push to `src/**`, `package.json`, `tsconfig.json`; do not edit it manually.
- Release: entry in `CHANGELOG.md` plus tag `vX.Y.Z`.
- Dependencies: `@aws-sdk/client-s3`, `@directus/extensions-sdk`.
